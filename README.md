# Отчёты отдела — Streamlit

Полный проект: главная с план–фактом и алертами; долёты, retention, депозитные воронки, NGR, активные дни, операционная пульсация; макеты CRM и реактивации. Названия бренда в интерфейсе нет.

## GitHub → Streamlit Community Cloud

1. Создайте **приватный** репозиторий: в комплекте есть реальные бизнес-показатели. Ограничьте доступ к приложению сотрудниками.
2. Распакуйте архив. Загрузите **содержимое** папки `streamlit_reports` в корень репозитория, сохраняя папки `data`, `reporting`, `.streamlit`. Один `app.py` без остальных файлов не работает.
3. В Streamlit создайте приложение, укажите репозиторий и ветку (обычно `main`). Main file path: `app.py`.
4. В дополнительных настройках выберите Python 3.12. Зависимости устанавливаются из `requirements.txt`.
5. После Deploy приложение открывается по выданной ссылке. Эта поставка сама ничего не публикует.

## Запуск на компьютере

Из папки проекта в PowerShell:

```powershell
py -m pip install -r requirements.txt
py -m streamlit run app.py
```

Страница откроется в браузере. Для работы Python-процесс должен оставаться запущенным.

## Что внутри

- `app.py`: Streamlit, главная, маршрутизация, алерты, CRM-макеты.
- `analytics.py`: сравнение периодов и пороги.
- `data/targets.csv`: цели, включая октябрь, ответственных и известный предыдущий факт.
- `data/manual_facts.csv`: ручной прогресс задач и CRM-факты. Поля `month,section,geo,metric,actual,as_of`; проценты в шкале 0–100. Пусто означает отсутствие данных.
- `data/alert_rules.json`: стартовые пороги алертов.
- `data/actuals.json`, `retention_cube.json`, `alerts_cube.json`: реальные снимки без идентификаторов игроков.
- `reporting/site`: готовые интерактивные HTML-разделы.
- `reporting/builders`: исходники всех генераторов.
- `refresh.py`: обновление всех снимков из новых CSV.
- `build_alerts.py`: потоковая агрегация для сравнения когорт.
- `test_app.py`: проверка правил и загрузки страниц.

Текущие HTML-графики встроены в Streamlit с собственной прокруткой. Они сохраняют фильтры, вкладки, цвета и расчёты. Главная написана на Streamlit; её график — Plotly. Переходы между разделами идут по `?page=...`; связанные CRM-ссылки сохраняют GEO и месяц. Обновление браузера сбрасывает несохранённые фильтры внутри встроенного HTML. Закреплена проверенная версия Streamlit 1.55.0; обновление зависимостей следует проверять тестами.

## Октябрьские цели

Долёты TR 350, AR 350, CO 300, IN 240. Open Rate триггерных писем: TR 25%, AR 20%, CO 20%. По IN Open Rate на скрине нет.

RR 3D на скрине не заполнен: план оставлен пустым. Нужно подтвердить определение RR 3D (точный D3 или D3+), прежде чем сопоставлять с текущим rolling retention.

Задачи команды: 5 прогретых email-доменов (предыдущий месяц 2), Communications 2.0 100%, CRM-дашборд 100%, эксперимент с таймингом PWA-пушей 100%, инбоксы по триггерным событиям 100%. Факты по задачам не выдуманы и заполняются вручную.

## Алерты

Пороговые сигналы, не тест статистической значимости. По умолчанию:
- конверсии: абсолютное изменение минимум 5 п.п.; база минимум 100 в каждом месяце;
- количества и средние: минимум 20% изменения; для количеств минимум 30 хотя бы в одном месяце;
- основные GEO TR, AR, CO, IN, глобальная пульсация ALL; прочие GEO раскрываются отдельно;
- показаны и снижения, и рост; рост расходов/выводов сам по себе не означает улучшение.

Сравнение по одинаковым дням месяца FTD: для окна D7 последний используемый день когорты — полный день данных минус 7. В предыдущем месяце берутся те же числа. В коротких месяцах берётся общая доступная длина. Окна депозитной воронки D7, возврат по интервалам D1–3/D4–7/D8–14/D15–30, NGR D0–D30. Суммы пульсации — одинаковые дни календарных месяцев. Сумма дневных игроков не равна уникальным игрокам месяца.

Lifetime-воронка и rolling retention исключены из алертов из-за разной длины наблюдения. Полное сравнение можно открыть по ссылке; оно показано над отчётом, чтобы отличать фиксированное окно алерта от общего периода отчёта. Новые октябрьские данные ещё не получены: отсутствие данных не считается падением до нуля. Для проверки реальных алертов выберите сентябрь. Пороги на экране действуют на текущий просмотр; постоянные настройки — в JSON.

Нельзя обнаружить сбой загрузки по отсутствующим строкам без внешнего контроля свежести. `--as-of` должен соответствовать настоящему срезу источника, а не дате ручного запуска скрипта.

## CRM-макеты

Страницы: welcome, 1→2, 2→3, 3→5, 5→8, долёты. Показатели и таблица писем пустые, с явной пометкой «макет». Нужны campaign_id/message_id, шаг цепочки, GEO, даты, sent/delivered/opened/clicked, контроль, ключ для соединения с DWH. Конверсии и NGR берутся из DWH; статусы рассылок — из CRM. Open Rate нужно согласовать как уникальные открытые сообщения / уникальные доставленные сообщения. Для эффекта рассылок нужны окно атрибуции и контрольная группа.

## Ежедневное обновление и Airflow

GitHub хранит код. Airflow выполняет SQL и готовит данные. Расписание Airflow в этом архиве не создано и соединения с DWH не настроены.

Подготовьте отдельную папку вне Git с `late_ftd.csv`, `user_lifecycle.csv`, `pulsation.csv`. Не загружайте исходные пользовательские CSV и секреты в Git. Затем:

```powershell
py refresh.py --input-dir C:/report_exports --as-of 2026-10-02
```

`--as-of` — фактическая дата среза; этот день считается неполным. Исходные player-level файлы не копируются в Git-проект. Пересчёт завершается до замены выходных файлов; отдельные файлы заменяются атомарно, но весь комплект не является атомарной транзакцией. Обновляйте приложение между пользовательскими сессиями или используйте версионные каталоги и переключение обоих путей ниже.

На собственном сервере Airflow может запускать этот скрипт после выгрузки, а приложение читать готовые файлы. Переменные `REPORT_DATA_DIR` и `REPORT_SITE_DIR` позволяют читать внешние каталоги (их структура такая же, как data и reporting/site). При действующем сеансе пользователь обновляет страницу, чтобы получить новый снимок.

Для Streamlit Community Cloud папка вашего локального Airflow недоступна напрямую. Варианты: пока вручную обновлять обезличенные снимки в приватном репозитории; затем настроить защищённое хранилище/API и загрузчик. Такой сетевой загрузчик не входит в текущую поставку, потому что адрес и способ авторизации ещё не заданы. Пароли/токены должны храниться в Secrets, не в коде.
